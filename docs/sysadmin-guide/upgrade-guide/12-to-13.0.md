
**Please read this entire document before commencing an upgrade.**

It is **required**  to migrate Azul OpenSearch data to new prefixes as part of this release.
This is required due to changes in the indexing of Azul content that enable faster and more efficient indexing and querying.

It is also **NOT** necessary to migrate Kafka data.

---

## azul-app

### infra

- **Important:** MinIO is now disabled by default. If your deployment depends on MinIO, ensure it is explicitly enabled during upgrade.

- If you are currently using the infra chart to deploy MinIO, it is strongly recommended that you migrate away from it during this release cycle.
  - MinIO support will be removed in 14.0.0.
  - SeaweedFS has been introduced as the recommended replacement.

### main

- **Important:** The `security.backend_opensearch_read_role` and `security.backend_opensearch_write_role` configuration options have been added.
  - The default read role is now `azul-access`.
  - Existing deployments may need to change this value back to `azul_read`, which was previously the default.
  - Alternatively, OpenSearch and OIDC role mappings can be updated to support the new `azul-access` role.
  - This change has been introduced to establish `azul-access` as the default role going forward.

- Renamed `PLUGIN_CAPE_AUTH_TOKEN` to `PLUGIN_SECRET_CAPE_AUTH_TOKEN`.

- Renamed the `plugins.generic.email-olemail` plugin to `email-mail-extract-msg`. Any existing configuration references should be updated accordingly.

- Changed `plugins.virustotal.pullFromApi` from a boolean value to an enum with the following supported values:
  - `vt`
  - `azure`
  - `disabled`

- The VirusTotal plugin now supports retrieving data from Azure Blob Storage using the following configuration options:

```yaml
plugins:
  virustotal:
    config:
      BLOB_CONTAINER: ""            # Azure Blob Storage container name.
      BLOB_FULL_PATH_FORMAT: ""     # Path format used to locate VirusTotal data.
      BLOB_FILE_NAME_FORMAT: ""     # Filename format of VirusTotal data blobs.
      BLOB_HOUR_GRACE_PERIOD: ""    # Delay, in hours, before downloading a blob (to remain behind live data).
      BLOB_STABILITY_PERIOD: ""     # Minimum age before a blob is considered stable for processing.
      BLOB_MAX_RETRY_ATTEMPTS: ""   # Maximum number of download retry attempts.
```

- Added a configurable chart-level security context:

```yaml
securityContext:
  runAsUser: 21000
  runAsGroup: 21000
  fsGroup: 21000
```

- Redis now supports a custom security context configuration:

```
redis:
  securityContext:
    runAsUser: null
    fsGroup: null
```
